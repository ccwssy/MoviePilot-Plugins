## v2.3.0 (2026-09-11)

### 新增
- 整理记录备份保留策略可配置，两种方式二选一：
  - 按条数（默认）：保留最近 N 条，默认 500 条（范围 50-5000）
  - 按天数：保留最近 N 天，默认 90 天（范围 1-3650），另设 5000 条硬上限防止无限增长
- 重复入库清理删除整理记录时同样先备份快照

---

## v2.2.0 (2026-09-11)

### 新增
- 整理记录删除前自动备份快照到插件数据 `deleted_history_backup`（最多保留 500 条），误判导致记录被删时仍可追溯与恢复
- URL 失效判定收紧：仅 `404 / 410` 判定源文件不存在；`401 / 403 / 429 / 5xx` 与网络异常统一视为「状态不确定」并保留，不再直接清理
- 网络异常或服务端错误（5xx）时自动冷却后重试一次
- 链接缓存增加严格判定标记：旧版宽松判定产生的「失效」缓存一律作废，改为实时复检
- 通知与日志新增「URL状态不确定(保留)」统计

---

## v2.1.0 (2026-09-11)

### 新增
- 源路径失效时先做 URL 可用性探测：URL 有效则判为「疑似移动」并保留入库文件，避免源目录/源文件改名或移动导致的误删
- 数据看板新增「疑似移动（源路径失效·URL有效，已保留）」分类
- 通知与日志增加「疑似移动保留」统计

### 说明
- 该行为依赖「URL可用性检查」开关；开关关闭时仍按原逻辑在源文件缺失时直接清理
- 源路径失效项的 URL 探测同样受线程数、冷却时间、每日上限与缓存有效期约束；仅当探测（或缓存）确认链接不可用时才执行清理
