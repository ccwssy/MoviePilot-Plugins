# Strm失效清理

> **MoviePilot V3 专用版本（v2.3.5）**，要求 MoviePilot >= 3.0.0。V2 用户请使用仓库 `plugins.v2` 目录下的 v1.1.9 版本。

## 概述

**Strm失效清理** 是一个用于 MoviePilot 的插件，通过转移记录对比 Emby 媒体库中的 STRM 文件与源 STRM 文件，如果源文件已删除，则自动通过 Emby API 删除对应的条目及附属文件。当整理记录中的源路径不存在但 STRM 内链接仍有效时，判定为「疑似移动」并保留，避免源目录改名或移动导致误删。

## 功能特性

- 扫描指定目录下的所有 `.strm` 文件
- 通过转移记录（transfer_history）查找每个 STRM 文件的源文件路径
- 检查磁盘上源 STRM 文件是否存在
- **重复入库清理**：同一源文件（src）对应多个入库文件（dest）时，只保留最新转移记录对应的文件，删除其他重复文件及 Emby 条目（通过精确 src 路径匹配，不同版本如 DV/HDR 不会被误删）
- 源文件缺失时，自动通过 Emby API 删除对应的单个条目（不会删除整个视频项目）
- **源路径失效二次确认**：整理记录中的源路径不存在时，先读取 STRM 内容做一次 URL 可用性探测，URL 有效则判为「疑似移动」并保留文件（需开启 URL可用性检查）
- **失效判定收紧**：仅 `404 / 410` 判定链接失效；`401 / 403 / 429 / 5xx` 与网络异常统一视为「状态不确定」并保留，网络异常或 5xx 会自动重试一次
- **整理记录快照备份**：删除整理记录前先把快照写入插件数据 `deleted_history_backup`，保留策略二选一（按条数 / 按天数），便于事后追溯与恢复
- 可选删除失效的 STRM 文件
- 可选删除附属文件（同名的 `.jpg` / `.nfo` 文件）
- 可选删除整理记录
- 自动递归删除空父目录
- 支持对无转移记录的 STRM 文件进行 URL 可用性检查（风险功能，需手动启用）
- 保留最近 500 条检查记录，可在插件详情页查看（按状态分类展示：重复入库清理、无转移记录、疑似移动、源文件缺失、检查失败、有效）

## 配置说明

| 配置项 | 说明 |
|--------|------|
| 启用插件 | 开启/关闭插件 |
| 发送通知 | 检查完成后是否发送通知消息 |
| 删除失效 STRM | 源文件缺失时，自动删除对应的 STRM 文件 |
| 删除附属文件(jpg/nfo) | 源文件缺失时，自动删除同名的 `.jpg` 和 `.nfo` 文件 |
| 删除整理记录 | 源文件缺失时，自动删除 MoviePilot 中的整理记录 |
| 执行周期(cron) | 5 位 cron 表达式，例如 `0 6 * * *` 表示每天早上 6 点执行 |
| 立即运行一次 | 勾选并保存后立即执行一次检查 |
| MP2入库后的STRM目录路径 | MP2 容器内看到的入库 STRM 文件目录，支持多行（每行一个目录） |
| Emby 地址 | Emby 服务器地址，留空则使用系统配置的媒体服务器 |
| Emby API Key | Emby API 密钥，留空则使用系统配置的媒体服务器 |
| 备份保留方式 | 页面居中：左侧「按天数」+ 天数输入框、右侧「按条数」+ 条数输入框，中间开关指向哪一侧即按哪种方式保留 |
| 备份保留条数 | 按条数模式下的上限，默认 500 条（范围 50-5000） |
| 备份保留天数 | 按天数模式下的保留时长，默认 90 天（范围 1-3650），另设 5000 条硬上限 |

### URL可用性检查（风险功能）

| 配置项 | 说明 |
|--------|------|
| 启用URL可用性检查 | 开启后对无转移记录、以及源路径已失效的 STRM 文件进行 HTTP 请求测试（仅 404/410 判定失效，其余状态码视为不确定并保留） |
| 线程数 | 并发检查线程数（1-3） |
| 冷却时间 | 每次请求后的等待时间（3-60秒），用于降低风控风险 |
| 每日检查上限 | 每天最多检查次数（10-500） |

## 使用方法

### 1. 安装插件

在 MoviePilot 插件市场中搜索 "Strm失效清理" 并安装。

### 2. 配置插件

进入插件配置页面，填写以下信息：
- **MP2入库后的STRM目录路径**：填写 MP2 容器内入库后的 STRM 文件目录
- **执行周期**：建议设置为每天执行一次，如 `0 6 * * *`
- 根据需要开启删除选项

### 3. 手动运行

配置完成后，勾选 **"立即运行一次"** 并保存，插件会立即执行一次检查。

### 4. 通过命令触发

在支持命令输入的渠道发送 `/strm_check` 即可手动触发检查。

### 5. 通过 API 触发

```
GET /api/v1/plugin/StrmLinkChecker/run_check?apikey=YOUR_API_KEY
```

## 工作流程

1. 扫描配置的 STRM 目录下的所有 `.strm` 文件
2. 通过转移记录（transfer_history）查找每个 STRM 文件的源文件路径（src）
3. 检查磁盘上源 STRM 文件是否存在
4. 源文件存在 → 记录为"有效"，跳过
5. 源文件不存在：
   - 已开启 URL可用性检查时，先读取 STRM 内容做一次 URL 探测；URL 有效 → 判为「疑似移动」并保留文件，不做清理
   - URL 不可用（或未开启 URL 检查）→ 执行清理：
     - 通过 Emby API 精确匹配路径并删除条目
     - 可选删除 STRM 文件本身
     - 可选删除同名的 `.jpg` / `.nfo` 附属文件
     - 可选删除整理记录
     - 自动递归删除空父目录
6. 发送通知（如已开启）

## 注意事项

- 删除 Emby 媒体库条目操作不可逆，请谨慎使用
- 建议先手动运行一次检查结果，确认无误后再开启定时任务
- 插件只删除精确匹配该 STRM 路径的 Emby 条目，不会删除整个视频项目
- 如果 Emby 地址和 API Key 留空，将自动使用系统配置的媒体服务器
- URL可用性检查可能触发网盘或文件服务器的风控机制，请谨慎使用
- 链接失效采用严格判定口径：只有 `404 / 410` 会触发清理，`403 / 429 / 5xx` 与网络异常只标记「状态不确定」并保留
